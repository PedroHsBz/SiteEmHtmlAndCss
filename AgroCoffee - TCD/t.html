Merge Sort — Tópico 01

Paradigma Dividir para Conquistar

Algoritmos baseados em divisão e conquista são, em geral, recursivos e dividem o problema em subproblemas de mesma natureza.

Algorithm DivideAndConquer procedure DIVIDEANDCONQUER(x) if x is small or simple then return solve(x) else decompose x into n subproblems: x[0], x[1], ..., x[n-1] for i ← 0 to n - 1 do y[i] ← DIVIDEANDCONQUER(x[i]) end for y ← combine y[0], y[1], ..., y[n-1] return y end if end procedure
// Divide and conquer generic template in C++ #include <iostream> #include <vector> #include <algorithm> using namespace std; #define FAST_IO ios_base::sync_with_stdio(false); cin.tie(NULL); int solveBaseCase(const vector<int>& nums, int idx) { return nums[idx]; } // Combines partial solutions int combine(int leftSol, int rightSol) { return max(leftSol, rightSol); } // Generic divide and conquer function int divideAndConquer(vector<int>& nums, int left, int right) { if (left >= right) { return solveBaseCase(nums, left); } int mid = left + (right - left) / 2; int leftSol = divideAndConquer(nums, left, mid); int rightSol = divideAndConquer(nums, mid + 1, right); return combine(leftSol, rightSol); } int main() { FAST_IO; vector<int> nums = {4, 8, 2, 7, 6, 3, 5, 1, 9, 10}; int maxElement = divideAndConquer(nums, 0, (int)nums.size() - 1); cout << "Maximum element: " << maxElement << '\n'; return 0; }
// Divide and conquer generic template in Java public class DivideAndConquer { private static int solveBaseCase(int[] nums, int idx) { return nums[idx]; } // Combines partial solutions private static int combine(int leftSol, int rightSol) { return Math.max(leftSol, rightSol); } public static int divideAndConquer(int[] nums, int left, int right) { if (left >= right) { return solveBaseCase(nums, left); } int mid = left + (right - left) / 2; int leftSol = divideAndConquer(nums, left, mid); int rightSol = divideAndConquer(nums, mid + 1, right); return combine(leftSol, rightSol); } public static void main(String[] args) { int[] nums = {4, 8, 2, 7, 6, 3, 5, 1, 9, 10}; int maxElement = divideAndConquer(nums, 0, nums.length - 1); System.out.println("Maximum element: " + maxElement); } }

Por que dividir e conquistar?

  • Aproveita melhor a memória cache: após a divisão, muitos dados usados na combinação já estão disponíveis em cache.
  • Reduz o número de acessos à memória, melhorando a performance.
  • Permite paralelização eficiente: com múltiplos processadores, o desempenho é potencializado.

Algoritmo de Ordenação Merge Sort

Funcionamento
  1. divide o vetor em duas metades (partição sempre no meio)
  2. conquer (ordena) recursivamente cada uma das metades
  3. combine (merge) as duas metades já ordenadas em um único vetor
Merge Sort — Tópico 02

Etapa de Merge: Funcionamento da Fusão

A etapa de merge combina duas sublistas já ordenadas em uma única lista também ordenada.

  • A fusão ocorre por meio da comparação simultânea dos elementos atuais das duas metades, copiando sempre o menor para uma lista auxiliar.
  • Quando uma das sublistas é totalmente percorrida, os elementos restantes da outra são copiados diretamente, pois já permanecem em ordem.
  • No Merge Sort, a fusão considera três posições dentro da mesma lista: início até meio, e meio + 1 até fim.
  • Utiliza-se uma lista auxiliar (helper) para armazenar temporariamente os valores intercalados, copiados de volta ao final.

Merge Sort — Tópico 04

Pseudocódigo do Merge Sort

Abordagem otimizada: o vetor auxiliar (helper) é alocado apenas uma vez, evitando sobrecarregar o Garbage Collector.

Algorithm Merge Sort (Otimizado) // Main routine: allocates helper once procedure MERGESORT(nums) n ← len(nums) if n > 1 then helper ← novoArray(n) MERGESORT(nums, helper, 0, n - 1) end if end procedure procedure MERGESORT(nums, helper, left, right) if left < right then middle ← ⌊(left + right) / 2⌋ MERGESORT(nums, helper, left, middle) MERGESORT(nums, helper, middle + 1, right) MERGE(nums, helper, left, middle, right) end if end procedure procedure MERGE(nums, helper, left, middle, right) // Copy target segment to helper for m ← left to right do helper[m] ← nums[m] end for i ← left; j ← middle + 1; k ← left while i ≤ middle and j ≤ right do if helper[i] ≤ helper[j] then nums[k] ← helper[i]; i ← i + 1 else nums[k] ← helper[j]; j ← j + 1 end if k ← k + 1 end while // Copy remaining elements from left side while i ≤ middle do nums[k] ← helper[i]; i ← i + 1; k ← k + 1 end while end procedure
// Optimized C++ implementation (single helper vector) #include <iostream> #include <vector> using namespace std; #define FAST_IO ios_base::sync_with_stdio(false); cin.tie(NULL); void merge(vector<int>& nums, vector<int>& helper, int left, int middle, int right) { for (int m = left; m <= right; m++) { helper[m] = nums[m]; } int i = left; int j = middle + 1; int k = left; while (i <= middle && j <= right) { if (helper[i] <= helper[j]) { nums[k++] = helper[i++]; } else { nums[k++] = helper[j++]; } } while (i <= middle) { nums[k++] = helper[i++]; } } void mergeSort(vector<int>& nums, vector<int>& helper, int left, int right) { if (left < right) { int middle = left + (right - left) / 2; mergeSort(nums, helper, left, middle); mergeSort(nums, helper, middle + 1, right); merge(nums, helper, left, middle, right); } } void mergeSort(vector<int>& nums) { vector<int> helper(nums.size()); mergeSort(nums, helper, 0, (int)nums.size() - 1); } int main() { FAST_IO; vector<int> nums = {4, 8, 2, 7, 6, 3, 5, 1, 9, 10}; mergeSort(nums); cout << "Sorted array: "; for (int val : nums) { cout << val << " "; } cout << '\n'; return 0; }
// Optimized Java implementation (single helper array) public class MergeSort { public void mergeSort(int[] nums) { int n = nums.length; if (n > 1) { int[] helper = new int[n]; mergeSort(nums, helper, 0, n - 1); } } private void mergeSort(int[] nums, int[] helper, int left, int right) { if (left < right) { int middle = left + (right - left) / 2; mergeSort(nums, helper, left, middle); mergeSort(nums, helper, middle + 1, right); merge(nums, helper, left, middle, right); } } private void merge(int[] nums, int[] helper, int left, int middle, int right) { for (int m = left; m <= right; m++) { helper[m] = nums[m]; } int i = left; int j = middle + 1; int k = left; while (i <= middle && j <= right) { if (helper[i] <= helper[j]) { nums[k++] = helper[i++]; } else { nums[k++] = helper[j++]; } } while (i <= middle) { nums[k++] = helper[i++]; } } public static void main(String[] args) { int[] nums = {4, 8, 2, 7, 6, 3, 5, 1, 9, 10}; MergeSort ms = new MergeSort(); ms.mergeSort(nums); System.out.print("Sorted array: "); for (int val : nums) { System.out.print(val + " "); } System.out.println(); } }
  • Vetor Auxiliar (helper): Alocado uma única vez no início, evitando novas alocações.
  • Ponteiros (i, j, k): Percorrem a metade esquerda, a metade direita e a posição de escrita.
  • Metade Direita Remanescente: Não precisa ser copiada de volta, pois já está posicionada corretamente no array original.

Pseudocódigo do Merge Sort In-Place

// Merge Sort In-Place: nenhum vetor auxiliar é alocado procedure MERGESORT(array, left, right) if left < right then middle ← ⌊(left + right) / 2⌋ MERGESORT(array, left, middle) MERGESORT(array, middle + 1, right) MERGE_INPLACE(array, left, middle, right) end if end procedure procedure MERGE_INPLACE(array, left, middle, right) i ← left j ← middle + 1 // Percorre as duas metades já ordenadas simultaneamente while i ≤ middle and j ≤ right do if array[i] ≤ array[j] then i ← i + 1 else value ← array[j] index ← j // desloca o bloco [i, j) uma posição à direita while index ≠ i do array[index] ← array[index - 1] index ← index - 1 end while array[i] ← value i ← i + 1 middle ← middle + 1 j ← j + 1 end if end while end procedure
// Merge Sort In-Place in C++ (O(1) extra space) void mergeInPlace(vector<int>& nums, int left, int middle, int right) { int i = left; int j = middle + 1; while (i <= middle && j <= right) { if (nums[i] <= nums[j]) { i++; } else { int value = nums[j]; int index = j; // Shift elements to the right while (index != i) { nums[index] = nums[index - 1]; index--; } nums[i] = value; i++; middle++; j++; } } } void mergeSortInPlace(vector<int>& nums, int left, int right) { if (left < right) { int middle = left + (right - left) / 2; mergeSortInPlace(nums, left, middle); mergeSortInPlace(nums, middle + 1, right); mergeInPlace(nums, left, middle, right); } }
// Merge Sort In-Place in Java (O(1) extra space) public void mergeInPlace(int[] nums, int left, int middle, int right) { int i = left; int j = middle + 1; while (i <= middle && j <= right) { if (nums[i] <= nums[j]) { i++; } else { int value = nums[j]; int index = j; // Shift elements to the right while (index != i) { nums[index] = nums[index - 1]; index--; } nums[i] = value; i++; middle++; j++; } } } public void sortInPlace(int[] nums, int left, int right) { if (left < right) { int middle = left + (right - left) / 2; sortInPlace(nums, left, middle); sortInPlace(nums, middle + 1, right); mergeInPlace(nums, left, middle, right); } }
Custo: Deslocamento (shift) de elementos · Impacto: Substitui o vetor auxiliar por cópias internas ao array
  • Sem vetor auxiliar: quando array[j] é menor, ele é inserido na posição de i deslocando os elementos intermediários uma posição à direita.
  • Espaço: cai de O(n) para O(1) de memória extra.
  • Tempo: cada deslocamento custa até O(n), o que degrada o merge e leva o algoritmo a O(n²) no pior caso — pior que os O(n log n) da versão com buffer.

Módulo 03 — Seção 02

Algoritmo de Ordenação
Quick Sort

Proposto por Tony Hoare em 1960: um algoritmo de divisão e conquista que particiona o vetor em torno de um pivô, sem custo extra na etapa de combinação.

Quick Sort — Tópico 01

Introdução ao Quick Sort

Um dos algoritmos de ordenação interna mais rápidos para uma ampla variedade de casos.

Contexto Histórico

  • Proposto por Tony Hoare em Moscou, União Soviética, em 1960; publicado em 1962.
  • Amplamente utilizado: implementado na função qsort da linguagem C e nas ordenações de tipos primitivos em Java.
  • Complexidade média: O(n log n) com baixo uso de memória.
  • Pior caso: O(n²), mas raro se bem implementado (ex.: escolha aleatória do pivô).

Divide and Conquer Strategy

  • Divide: particionar Array[left..right] em dois subarrays, de modo que todo elemento à esquerda do pivô seja menor ou igual a ele, e todo elemento à direita seja maior ou igual.
  • Conquer: ordenar os dois subarrays recursivamente.
  • Combine: como os subarrays já estão ordenados localmente (in-place), não é necessário nenhum trabalho extra para combiná-los.

Algoritmo de Ordenação Quick Sort

Funcionamento
  1. choose (escolhe) um elemento como pivô (aqui, o último do intervalo)
  2. partition (particiona) o vetor movendo os menores ou iguais ao pivô para a esquerda e os maiores para a direita
  3. conquer / sort (ordena) recursivamente as duas partições resultantes

Quick Sort — Tópico 03

Pseudocódigo — Particionamento de Lomuto

Esquema de Lomuto: um ponteiro de leitura (j) e um de escrita (i) caminham juntos da esquerda para a direita, com o pivô no último elemento[cite: 3].

Algorithm Quick Sort procedure QUICKSORT(nums, left, right) if left < right then pivot_index ← PARTITION(nums, left, right) QUICKSORT(nums, left, pivot_index - 1) QUICKSORT(nums, pivot_index + 1, right) end if end procedure // Partitioning with rightmost pivot procedure PARTITION(nums, left, right) pivot ← nums[right] i ← left - 1 for j ← left to right - 1 do if nums[j] ≤ pivot then i ← i + 1 SWAP nums[i] ↔ nums[j] end if end for SWAP nums[i + 1] ↔ nums[right] return i + 1 end procedure
// Traditional Lomuto partition in C++ (rightmost pivot) #include <iostream> #include <vector> #include <utility> using namespace std; #define FAST_IO ios_base::sync_with_stdio(false); cin.tie(NULL); int partition(vector<int>& nums, int left, int right) { int pivot = nums[right]; int i = left - 1; for (int j = left; j < right; j++) { if (nums[j] <= pivot) { i++; swap(nums[i], nums[j]); } } swap(nums[i + 1], nums[right]); return i + 1; } void quickSort(vector<int>& nums, int left, int right) { if (left < right) { int pivotIndex = partition(nums, left, right); quickSort(nums, left, pivotIndex - 1); quickSort(nums, pivotIndex + 1, right); } } int main() { FAST_IO; vector<int> nums = {4, 8, 2, 7, 6, 3, 5, 1, 9, 10}; quickSort(nums, 0, (int)nums.size() - 1); cout << "Sorted array: "; for (int val : nums) { cout << val << " "; } cout << '\n'; return 0; }
// Traditional Lomuto partition in Java (rightmost pivot) public class QuickSort { public void quickSort(int[] nums, int left, int right) { if (left < right) { int pivotIndex = partition(nums, left, right); quickSort(nums, left, pivotIndex - 1); quickSort(nums, pivotIndex + 1, right); } } private int partition(int[] nums, int left, int right) { int pivot = nums[right]; int i = left - 1; for (int j = left; j < right; j++) { if (nums[j] <= pivot) { i++; int temp = nums[i]; nums[i] = nums[j]; nums[j] = temp; } } int temp = nums[i + 1]; nums[i + 1] = nums[right]; nums[right] = temp; return i + 1; } public static void main(String[] args) { int[] nums = {4, 8, 2, 7, 6, 3, 5, 1, 9, 10}; QuickSort qs = new QuickSort(); qs.quickSort(nums, 0, nums.length - 1); System.out.print("Sorted array: "); for (int val : nums) { System.out.print(val + " "); } System.out.println(); } }
  • Ponteiro i: limite da região já confirmada como ≤ pivô (escrita). Ponteiro j: varredura (leitura)[cite: 3].
  • Vantagem: o esquema mais simples de entender, provar e codificar. Ao final, o pivô vai para o ponto divisor e nunca mais precisa ser movido[cite: 3].
  • Desvantagem: executa substancialmente mais acessos e trocas de memória. Com todos os elementos iguais, a partição degenera em (n−1) e 0 → O(n²)[cite: 3].
Quick Sort — Tópico 04

Os Três Esquemas de Particionamento

O Quick Sort é um esqueleto recursivo fixo; o que muda entre as implementações clássicas é como o vetor é particionado.

01 · LOMUTO

Varredura unidirecional

Pivô no último elemento. Devolve o índice final do pivô; recursão em [l, p−1] e [p+1, r].

02 · HOARE

Ponteiros convergentes

Pivô por valor (tipicamente o do meio). Devolve um ponto de corte j; recursão em [l, j] e [j+1, r].

03 · GRIES

Convergente com invariante

Pivô no primeiro elemento. Converge como Hoare, mas restaura o pivô na posição exata, como Lomuto.

Todos particionam em O(n) e usam O(1) de memória auxiliar. A diferença está no número de acessos/trocas, no tratamento de duplicatas e no contrato de retorno — que muda a chamada recursiva.
Quick Sort — Tópico 05

Pseudocódigo — Particionamento de Hoare

O esquema original de 1961: dois ponteiros partem dos extremos e caminham em direção ao centro, trocando os pares fora de lugar[cite: 3].

Algorithm Hoare Partition procedure QUICKSORT(nums, left, right) if left < right then j ← HOARE_PARTITION(nums, left, right) QUICKSORT(nums, left, j) // j is part of left sub-array QUICKSORT(nums, j + 1, right) end if end procedure // Convergent pointers; pivot selected by VALUE procedure HOARE_PARTITION(nums, left, right) pivot ← nums[(left + right) / 2] i ← left - 1 j ← right + 1 loop repeat i ← i + 1 until nums[i] ≥ pivot repeat j ← j - 1 until nums[j] ≤ pivot if i ≥ j then return j // split index end if SWAP nums[i] ↔ nums[j] end loop end procedure
// Hoare bidirectional partition in C++ #include <iostream> #include <vector> #include <utility> using namespace std; #define FAST_IO ios_base::sync_with_stdio(false); cin.tie(NULL); int hoarePartition(vector<int>& nums, int low, int high) { int pivot = nums[low + (high - low) / 2]; int i = low - 1; int j = high + 1; while (true) { do { i++; } while (nums[i] < pivot); do { j--; } while (nums[j] > pivot); if (i >= j) { return j; } swap(nums[i], nums[j]); } } void quickSortHoare(vector<int>& nums, int low, int high) { if (low < high) { int j = hoarePartition(nums, low, high); quickSortHoare(nums, low, j); // DO NOT use j - 1 quickSortHoare(nums, j + 1, high); } } int main() { FAST_IO; vector<int> nums = {4, 8, 2, 7, 6, 3, 5, 1, 9, 10}; quickSortHoare(nums, 0, (int)nums.size() - 1); cout << "Sorted array: "; for (int val : nums) { cout << val << " "; } cout << '\n'; return 0; }
// Hoare bidirectional partition in Java public class QuickSortHoare { public void sort(int[] nums, int low, int high) { if (low < high) { int j = partition(nums, low, high); sort(nums, low, j); sort(nums, j + 1, high); } } private int partition(int[] nums, int low, int high) { int pivot = nums[low + (high - low) / 2]; int i = low - 1; int j = high + 1; while (true) { do { i++; } while (nums[i] < pivot); do { j--; } while (nums[j] > pivot); if (i >= j) { return j; } int t = nums[i]; nums[i] = nums[j]; nums[j] = t; } } public static void main(String[] args) { int[] nums = {4, 8, 2, 7, 6, 3, 5, 1, 9, 10}; QuickSortHoare qs = new QuickSortHoare(); qs.sort(nums, 0, nums.length - 1); System.out.print("Sorted array: "); for (int val : nums) { System.out.print(val + " "); } System.out.println(); } }
  • Vantagem: realiza cerca de 3× menos trocas que Lomuto em média e lida naturalmente bem com vetores cheios de elementos duplicados (as trocas "inúteis" dividem o vetor ao meio)[cite: 3].
  • Desvantagem: não posiciona o pivô em seu índice final. Devolve apenas um ponto de corte j, com a garantia nums[l..j] ≤ nums[j+1..r][cite: 3].
  • Armadilha clássica: usar nums[right] como pivô ou recorrer em [l, j-1] gera laço infinito ou perda de elementos — erros sutis de off-by-one[cite: 3].
Quick Sort — Tópico 06

Pseudocódigo — Particionamento de Gries

De The Science of Programming (1981): a rotina é derivada a partir da invariante, e não ajustada por tentativa e erro[cite: 3].

Algorithm Gries Partition // LOOP INVARIANT: // nums[low+1 .. i-1] ≤ pivot ∧ nums[j+1 .. high] > pivot // nums[i .. j] = uninspected region procedure GRIES_PARTITION(nums, low, high) pivot ← nums[low] i ← low + 1 j ← high while i ≤ j do while i ≤ j and nums[i] ≤ pivot do i ← i + 1 end while while i ≤ j and nums[j] > pivot do j ← j - 1 end while if i < j then SWAP nums[i] ↔ nums[j] i ← i + 1 j ← j - 1 end if end while SWAP nums[low] ↔ nums[j] // restore pivot return j // exact final index of pivot end procedure
// Gries partition in C++ (convergent with restored pivot) #include <iostream> #include <vector> #include <utility> using namespace std; #define FAST_IO ios_base::sync_with_stdio(false); cin.tie(NULL); int griesPartition(vector<int>& nums, int low, int high) { int pivot = nums[low]; int i = low + 1; int j = high; while (i <= j) { while (i <= j && nums[i] <= pivot) { i++; } while (i <= j && nums[j] > pivot) { j--; } if (i < j) { swap(nums[i], nums[j]); i++; j--; } } swap(nums[low], nums[j]); return j; } void quickSortGries(vector<int>& nums, int low, int high) { if (low < high) { int p = griesPartition(nums, low, high); quickSortGries(nums, low, p - 1); // pivot is already in place quickSortGries(nums, p + 1, high); } } int main() { FAST_IO; vector<int> nums = {4, 8, 2, 7, 6, 3, 5, 1, 9, 10}; quickSortGries(nums, 0, (int)nums.size() - 1); cout << "Sorted array: "; for (int val : nums) { cout << val << " "; } cout << '\n'; return 0; }
// Gries partition in Java (convergent with restored pivot) public class QuickSortGries { public void sort(int[] nums, int low, int high) { if (low < high) { int p = partition(nums, low, high); sort(nums, low, p - 1); sort(nums, p + 1, high); } } private int partition(int[] nums, int low, int high) { int pivot = nums[low]; int i = low + 1; int j = high; while (i <= j) { while (i <= j && nums[i] <= pivot) { i++; } while (i <= j && nums[j] > pivot) { j--; } if (i < j) { int t = nums[i]; nums[i] = nums[j]; nums[j] = t; i++; j--; } } int t = nums[low]; nums[low] = nums[j]; nums[j] = t; return j; } public static void main(String[] args) { int[] nums = {4, 8, 2, 7, 6, 3, 5, 1, 9, 10}; QuickSortGries qs = new QuickSortGries(); qs.sort(nums, 0, nums.length - 1); System.out.print("Sorted array: "); for (int val : nums) { System.out.print(val + " "); } System.out.println(); } }
  • Diferencial: junta a eficiência do movimento convergente de Hoare com a propriedade de Lomuto de devolver o índice exato do pivô — a recursão volta a ser [l, p−1] e [p+1, r][cite: 3].
  • Filosofia: construído para prova formal de corretude. Ao eliminar os repeat…until aninhados de Hoare, as condições de parada ficam explícitas e previsíveis[cite: 3].
  • Ganho pedagógico: cada laço interno só avança enquanto a invariante continua válida; o pivô fora da região [i..j] nunca é movido por engano[cite: 3].

Comparação Lado a Lado dos Três Esquemas

Confronte diretamente as diferenças na escolha do pivô, na condição de avanço dos ponteiros e nos limites da chamada recursiva.

01 · LOMUTO nums[right]
// Lomuto: Unidirectional procedure PARTITION(nums, left, right) pivot ← nums[right] i ← left - 1 for j ← left to right - 1 do if nums[j] ≤ pivot then i ← i + 1 SWAP nums[i] ↔ nums[j] end if end for SWAP nums[i + 1] ↔ nums[right] return i + 1 end procedure procedure QUICKSORT(nums, left, right) if left < right then p ← PARTITION(nums, left, right) QUICKSORT(nums, left, p - 1) QUICKSORT(nums, p + 1, right) end if end procedure
Retorno: p (índice final) · Subdivisão: [l, p-1] / [p+1, r]
02 · HOARE nums[mid]
// Hoare: Convergent procedure HOARE_PARTITION(nums, left, right) pivot ← nums[(left + right) / 2] i ← left - 1; j ← right + 1 loop repeat i ← i + 1 until nums[i] ≥ pivot repeat j ← j - 1 until nums[j] ≤ pivot if i ≥ j then return j end if SWAP nums[i] ↔ nums[j] end loop end procedure procedure QUICKSORT(nums, left, right) if left < right then j ← HOARE_PARTITION(nums, left, right) QUICKSORT(nums, left, j) QUICKSORT(nums, j + 1, right) end if end procedure
Retorno: j (corte) · Subdivisão: [l, j] / [j+1, r]
03 · GRIES nums[low]
// Gries: Convergent + Restored procedure GRIES_PARTITION(nums, low, high) pivot ← nums[low] i ← low + 1; j ← high while i ≤ j do while i ≤ j and nums[i] ≤ pivot do i ← i + 1 while i ≤ j and nums[j] > pivot do j ← j - 1 if i < j then SWAP nums[i] ↔ nums[j] i ← i + 1; j ← j - 1 end if end while SWAP nums[low] ↔ nums[j] return j end procedure procedure QUICKSORT(nums, low, high) if low < high then p ← GRIES_PARTITION(nums, low, high) QUICKSORT(nums, low, p - 1) QUICKSORT(nums, p + 1, high) end if end procedure
Retorno: p (índice final) · Subdivisão: [l, p-1] / [p+1, r]
01 · LOMUTO (C++) nums[right]
int partitionLomuto(vector<int>& nums, int l, int r) { int pivot = nums[r]; int i = l - 1; for (int j = l; j < r; j++) { if (nums[j] <= pivot) { i++; swap(nums[i], nums[j]); } } swap(nums[i + 1], nums[r]); return i + 1; } void qsLomuto(vector<int>& nums, int l, int r) { if (l < r) { int p = partitionLomuto(nums, l, r); qsLomuto(nums, l, p - 1); qsLomuto(nums, p + 1, r); } }
Pivô: excluído das chamadas recursivas (`p - 1` e `p + 1`).
02 · HOARE (C++) nums[mid]
int partitionHoare(vector<int>& nums, int l, int r) { int pivot = nums[l + (r - l) / 2]; int i = l - 1, j = r + 1; while (true) { do { i++; } while (nums[i] < pivot); do { j--; } while (nums[j] > pivot); if (i >= j) return j; swap(nums[i], nums[j]); } } void qsHoare(vector<int>& nums, int l, int r) { if (l < r) { int j = partitionHoare(nums, l, r); qsHoare(nums, l, j); // j INCLUSO qsHoare(nums, j + 1, r); } }
Pivô: não fixado; o ponto de corte j faz parte da esquerda!
03 · GRIES (C++) nums[low]

Pivô: restaurado em `j`, permitindo exclusão (`p - 1` e `p + 1`).

Quick Sort — Tópico 11

Evitando o Pior Caso I: Randomized Partition

O pior caso O(n²) não é culpa do particionamento, e sim da escolha do pivô: basta o pivô ser sempre o menor (ou o maior) do intervalo.

// Randomized pivot selection in C++ #include <vector> #include <random> #include <utility> using namespace std; int randomizedPartition(vector<int>& nums, int low, int high) { static mt19937 rng{random_device{}()}; uniform_int_distribution<int> dist(low, high); int r = dist(rng); swap(nums[r], nums[high]); // Lomuto expects pivot on the right return partition(nums, low, high); }
  • Ideia: um adversário pode construir a entrada que quebra um pivô fixo, mas não consegue prever um sorteio. O pior caso deixa de depender da entrada e passa a depender do acaso.
  • Garantia: o pior caso O(n²) continua possível, mas sua probabilidade é desprezível. O tempo esperado passa a ser O(n log n) para qualquer entrada.
  • Custo: apenas uma troca extra e uma chamada ao gerador por partição — praticamente nada diante do ganho.

Quick Sort — Tópico 12

Evitando o Pior Caso II: Mediana de Três

Em vez de sortear, estima-se a mediana do intervalo amostrando três candidatos: nums[low], nums[mid] e nums[high].

// Median of three pivot selection in C++ #include <vector> #include <utility> using namespace std; int medianOfThree(vector<int>& nums, int low, int high) { int mid = low + (high - low) / 2; if (nums[mid] < nums[low]) { swap(nums[mid], nums[low]); } if (nums[high] < nums[low]) { swap(nums[high], nums[low]); } if (nums[high] < nums[mid]) { swap(nums[high], nums[mid]); } // Now: nums[low] <= nums[mid] <= nums[high] swap(nums[mid], nums[high - 1]); // Hide pivot at high - 1 return nums[high - 1]; }
  • Vantagem sobre o sorteio: é determinístico (execuções reproduzíveis, útil em depuração e em provas de mesa) e não paga o custo do gerador aleatório.
  • Efeito colateral útil: as três comparações já deixam nums[low] e nums[high] como sentinelas, permitindo enxugar os testes de limite dentro do laço.
  • Elimina o caso patológico mais comum: vetores já ordenados ou invertidos passam a ser divididos exatamente ao meio.
  • Limite: ainda é possível construir uma entrada adversarial que force O(n²); a proteção é heurística, não probabilística. Variantes usam ninther para vetores grandes.
Na prática, bibliotecas combinam as duas ideias: o introsort parte da mediana de três e, se a profundidade da recursão passar de 2·log₂n, troca para Heap Sort — garantindo O(n log n) no pior caso.

Merge Sort vs Quick Sort

Ambos são O(n log n) em média, mas fazem escolhas de projeto bem diferentes.

Na prática, o Quick Sort costuma ser mais rápido em memória interna por ter fatores constantes menores e melhor uso de cache, apesar do risco teórico de O(n²). O Merge Sort é preferido quando a estabilidade ou o pior caso garantido são essenciais.

Resumo: Divisão e Conquista

Pontos-Chave
  1. Merge Sort garante O(n log n) em todos os casos, ao custo de espaço extra O(n) e não ser in-place.
  2. Quick Sort é geralmente o mais rápido na prática, mas seu pior caso O(n²) exige boas estratégias de escolha de pivô.
  3. Ambos superam largamente os algoritmos quadráticos (Bubble, Selection, Insertion) para vetores grandes.
Conclusão do Módulo 03

Próximo Passo: Pesquisa em Dados

A grande motivação prática para ordenar dados reside em acelerar pesquisas futuras, reduzindo a busca de O(n) para O(log n).

1. Pesquisa Linear vs Pesquisa Binária

  • Pesquisa Linear (Sequencial): varre elemento a elemento. Funciona em vetores desordenados, mas opera em tempo O(n).
  • Pesquisa Binária: requer vetor previamente ordenado. Aplica divisão e conquista descartando metade do espaço a cada passo, operando em O(log n).
  • Impacto de Desempenho: em uma base com 1.000.000 de registros, a linear exige até 1.000.000 comparações; a binária atinge o resultado em no máximo 20 comparações.

2. Métodos Avançados e Próximas Estruturas

  • Interpolação e Busca Exponencial: calculam posições prováveis da chave, aproximando o custo médio a O(log log n) em dados uniformes.
  • Árvores Binárias de Busca (BST): estruturam buscas em O(log n) permitindo inserções e remoções contínuas sem realocação estática.
  • Árvores Balanceadas (AVL e Rubro-Negras): neutralizam a degeneração do pior caso da BST, mantendo garantia estrita de complexidade logarítmica.
